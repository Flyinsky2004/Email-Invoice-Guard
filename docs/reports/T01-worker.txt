Behavior implemented
- microsoft.New(repo, cfg, client) *Source; Type/ListFolders/Sync (core.MailSource) and Begin/CompleteAuthorization (core.AccountOnboarding).
- OAuth: random state (32 bytes) + verifier (48 bytes, base64url), S256 challenge, session keyed by SHA-256(state), purpose-bound, TTL (default 10m), one-time ConsumeSession, actor bound into payload and applied as account OwnerUserID.
- Defaults: tenant "consumers", authority login.microsoftonline.com, Graph v1.0; scopes "Mail.Read offline_access User.Read" (User.Read only for GET /me address discovery).
- CompleteAuthorization: consumes session, exchanges code with code_verifier, validates /me mail or userPrincipalName, writes account+credential in one Store.Transaction when the repository is a core.Store, otherwise sequentially. Same provider+address reauthorization reuses the existing account ID and CreatedAt; a different owner is rejected with core.ErrUnauthorized.
- Refresh: per-account mutex, independent accounts, rotated refresh token persisted, old token preserved when absent, proactive refresh near expiry, 401 refresh once then retry, invalid_grant/interaction_required/consent_required/login_required -> core.ErrReauthorization. No credentials in errors or logs.
- Graph: Prefer IdType="ImmutableId" on every Graph request; HTML body preference with local HTML->text normalization; pinned Graph/authority origins before bearer attachment; per-request redirect pinning (a redirect may not leave the origin of the request that produced it); HTTPS enforced except explicitly configured loopback mocks.
- Folders (rev 2): Graph v1.0 mailFolder has no wellKnownName property. Roles are resolved through GET /me/mailFolders/{inbox|sentitems|drafts|deleteditems|junkemail}?$select=id and matched by folder id, so localized names such as "收件箱" map correctly. The real listing selects only id,displayName,parentFolderId,childFolderCount; childFolders are traversed recursively (depth and page bounds) so nested custom folders are discoverable. Inbox is enabled by default; stored enabled choices (including custom child folders) are preserved. Missing well-known folders (404) are skipped.
- Delta: per-folder delta, bounded $top=50, opaque nextLink/deltaLink preserved as candidate cursor (provider never persists), full first traversal builds baseline, local historical classification (no receivedDateTime filter), 410 rebuilds a safe baseline, tombstones skipped without notification, recipients/sender/message-id/headers/body/webLink mapped, conservative cross-folder fingerprint.
- Attachments (rev 3): metadata is listed through GET /me/messages/{id}/attachments?$select=id,name,contentType,size and every @odata.nextLink page is traversed (no $expand, no contentBytes). Attachment ids are deterministic account-scoped 32-hex hashes of account+message+Graph id, so two accounts cannot collide and re-sync is stable. The raw Graph attachment id is intentionally not retained because attachments are never downloaded.
- Response size (rev 2): successful Graph payloads are streamed through json.Decoder without a byte cap, so legitimate bodies larger than 8 MiB are delivered intact. Token/error responses remain bounded at 1 MiB.
- HTML normalization (rev 2): uses golang.org/x/net/html (already pinned in go.mod as an indirect module; no go.mod/go.sum edit) to walk the DOM, skip script/style/head/noscript/template, emit block boundaries as newlines, decode entities and normalize whitespace. Text inside unknown or malformed elements is preserved.
- Retry: 429/503 honor the full server Retry-After (no truncation), bounded attempts, context-aware sleeps; transport timeouts retried with capped local backoff.
- oauth.New(source): GET-only callback, generic error bodies, no echo of state/code/errors, Cache-Control no-store, Referrer-Policy no-referrer, nosniff, CSP default-src 'none'.

Security risks and limitations
- No live Microsoft app registration or real accounts were exercised; all HTTP is mocked.
- PKCE verifier confidentiality depends on storage encrypting SecureSession.Payload as frozen schema requires.
- Retry-After waits can be long (server value); only context cancellation/client timeout bounds them. This is intentional to avoid early retries.
- Attachment metadata requires a second Graph request per message with hasAttachments, plus one request per additional page; a failure fails the page and is retried by the sync engine rather than silently dropping metadata.
- Attachment ids are provider-derived hashes, not Graph ids. If a future feature needs to download an attachment, the Graph id must be re-fetched or the contract extended.
- HTML->text is parser-based but intentionally conservative: it drops script/style/head content and collapses whitespace, so preformatted layout is not preserved.
- Folder discovery issues 5 well-known probes plus recursive child listing per call; large folder trees cost additional requests but remain depth/page bounded.
- Account takeover is rejected only when ListAccounts exposes the existing row; see storage dependency above.
