### 3.1 Language selection

- New SQLite setting key `language`, values exactly `en` and `zh-CN`.
- `/settings language` with no argument shows the current language.
- `/settings language en` and `/settings language zh-CN` set it. Accept `zh`, `zh-cn`, `cn`
  as aliases for `zh-CN`; reject anything else with a clear error in the current language.
- Persist with the existing `store.SetSetting`; read with `store.GetSetting`.
- Missing setting or `core.ErrNotFound` means `zh-CN`. A stored invalid value also falls back
  to `zh-CN` and logs a warning.
- The setting is read per incoming message, per callback and once per delivery, so a change
  applies without restart. Do not cache it across updates.

### 3.2 Translation mechanism

Add `internal/telegram/i18n.go` (and tests) with:

```go
type lang string
const (
    langEN lang = "en"
    langZH lang = "zh-CN"
)
```

A complete catalog for both languages, keyed by stable identifiers (for example
`help`, `status.header`, `invoice.paid`, `manual.summary.header`, `error.unauthorized`).
Provide a helper such as `func (b *Bot) text(ctx context.Context, key string, args ...any) string`
or a small `translator` value passed down the call chain. The design is yours, but:

- Every user-visible string must come from the catalog; no English literal may remain in a
  user-facing path.
- Missing keys must be a test failure, not a silent English fallback. Add a test that iterates
  both catalogs and asserts identical key sets.
- Dynamic values stay escaped exactly as today. Static catalog text is trusted, but any
  interpolated value must pass through `escape`.
- Command names, callback actions, setting keys and stored values remain ASCII and unchanged.

### 3.3 What must be translated

All user-visible text in these paths:
- `commands.go`: `/start`, `/help` (including the command list), `/add`, `/accounts`,
  `/remove`, `/sync`, `/latest`, `/search`, `/invoices` and its `pending|paid|overdue|review`
  variants, `/assets`, `/providers`, `/status`, `/settings` and all subcommands, unknown
  command, usage errors, empty-list messages, list titles.
- `callbacks.go`: payment prompt, confirm/undo/cancel acknowledgements and errors, email and
  invoice detail titles, asset history, account removal.
- `delivery.go` + `format.go`: email notification labels, invoice notification labels,
  reminder notes, status words, money/date labels, manual reminder summary header and
  per-occurrence lines, plan detail, pending list, history.
- `settings.go`: current values, validation errors, folder listing/toggle text.
- `auth.go`: inline button labels ("Mark paid", "Undo paid", "Original mail", "View invoice",
  manual confirm/revoke/view/history/delete buttons, wizard buttons).
- `manual.go` / wizard: every prompt, step label, validation error, confirmation page and
  cancel/timeout message added by T12.
- `api.go` / `bot.go`: only strings that reach the user; internal log messages stay English.

Do not translate: log messages, error values returned to Go callers, SQL, callback data,
command names, email subjects/bodies, merchant names, invoice numbers, asset hostnames.

### 3.4 Exported contract functions

`FormatEmail(core.NormalizedEmail, core.MailAccount) []string` and
`FormatInvoice(core.Invoice, core.MailAccount) []string` keep their exact signatures and
remain English for external acceptance. The bot must call language-aware internal variants.
Document this in the package comment.

### 3.5 Limits and safety

- `maxMessageUnits = 4096` UTF-16 units and the existing chunker must still hold for both
  languages; Chinese text is denser, so add at least one long-message test in each language.
- Inline keyboard labels have practical length limits; keep translated labels short.
- Callback data must stay ≤64 bytes and unchanged by language.
- HTML must remain valid after translation; escape every interpolated value.
- Authorization behavior must not change: user whitelist and chat check remain first.

### 3.6 Tests

- Catalog completeness: both languages have identical key sets; no empty values.
- Default language is `zh-CN` when the setting is absent.
- `/settings language zh-CN|en|zh|cn` persists and switches; invalid value is rejected and
  does not change the stored value.
- One representative command, one callback, one email notification, one invoice
  notification and one manual reminder summary rendered in both languages, asserting
  distinctive translated substrings and no English leakage in the Chinese path.
- Escaping: a user-supplied title containing `<b>&` is escaped in both languages.
- Limits: a long email and a long manual summary stay within 4096 UTF-16 per part in both
  languages.
- Callback data for manual confirm/revoke is identical in both languages.
- Existing tests that assert English text must be updated only where the default language
  now changes the output; keep English-path assertions by setting `language=en` explicitly.
