Migration `0002_manual_reminders.sql` is additive and uses exactly this DDL:

```sql
CREATE TABLE IF NOT EXISTS manual_reminder_plans (
    id TEXT PRIMARY KEY, title TEXT NOT NULL, provider_name TEXT NOT NULL DEFAULT '',
    asset_id TEXT REFERENCES assets(id), description TEXT NOT NULL DEFAULT '',
    amount_minor INTEGER, currency TEXT,
    billing_day INTEGER NOT NULL CHECK (billing_day BETWEEN 1 AND 31),
    reminder_time TEXT NOT NULL, timezone TEXT NOT NULL,
    payment_url TEXT NOT NULL DEFAULT '', notes TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL CHECK (status IN ('ACTIVE','PAUSED','CANCELLED')),
    next_due_date TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
    cancelled_at TEXT,
    CHECK ((amount_minor IS NULL AND currency IS NULL)
        OR (amount_minor IS NOT NULL AND currency IS NOT NULL))
);
CREATE INDEX IF NOT EXISTS idx_manual_plans_status_due
    ON manual_reminder_plans(status, next_due_date);
CREATE TABLE IF NOT EXISTS manual_reminder_occurrences (
    id TEXT PRIMARY KEY, plan_id TEXT NOT NULL REFERENCES manual_reminder_plans(id),
    due_date TEXT NOT NULL, amount_minor_snapshot INTEGER, currency_snapshot TEXT,
    payment_status TEXT NOT NULL CHECK (payment_status IN
        ('PENDING_CONFIRMATION','PAID_CONFIRMED','CANCELLED')),
    notified_at TEXT, confirmed_at TEXT, confirmed_by INTEGER,
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
    UNIQUE (plan_id, due_date)
);
CREATE INDEX IF NOT EXISTS idx_manual_occ_status
    ON manual_reminder_occurrences(payment_status, due_date);
CREATE TABLE IF NOT EXISTS manual_reminder_dispatches (
    id TEXT PRIMARY KEY, plan_id TEXT NOT NULL REFERENCES manual_reminder_plans(id),
    outbox_id TEXT NOT NULL REFERENCES delivery_outbox(id), local_date TEXT NOT NULL,
    kind TEXT NOT NULL CHECK (kind IN ('DAILY_SUMMARY')),
    status TEXT NOT NULL CHECK (status IN
        ('PENDING','SENDING','SENT','FAILED','UNKNOWN','SKIPPED')),
    created_at TEXT NOT NULL, sent_at TEXT,
    UNIQUE (outbox_id), UNIQUE (plan_id, local_date, kind)
);
CREATE INDEX IF NOT EXISTS idx_manual_dispatches_plan
    ON manual_reminder_dispatches(plan_id, local_date);
CREATE TABLE IF NOT EXISTS manual_reminder_dispatch_occurrences (
    dispatch_id TEXT NOT NULL REFERENCES manual_reminder_dispatches(id),
    occurrence_id TEXT NOT NULL REFERENCES manual_reminder_occurrences(id),
    PRIMARY KEY (dispatch_id, occurrence_id)
);
CREATE INDEX IF NOT EXISTS idx_manual_dispatch_occ_occurrence
    ON manual_reminder_dispatch_occurrences(occurrence_id);
CREATE TABLE IF NOT EXISTS manual_reminder_events (
    id TEXT PRIMARY KEY, plan_id TEXT NOT NULL REFERENCES manual_reminder_plans(id),
    occurrence_id TEXT REFERENCES manual_reminder_occurrences(id),
    event_type TEXT NOT NULL CHECK (event_type IN (
        'PLAN_CREATED','PLAN_UPDATED','PLAN_PAUSED','PLAN_RESUMED','PLAN_CANCELLED',
        'OCCURRENCE_CREATED','REMINDER_SENT','PAYMENT_CONFIRMED',
        'PAYMENT_CONFIRMATION_REVOKED','OCCURRENCE_CANCELLED')),
    actor_id INTEGER NOT NULL DEFAULT 0, event_at TEXT NOT NULL,
    metadata TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX IF NOT EXISTS idx_manual_events_plan
    ON manual_reminder_events(plan_id, event_at);
```

Behavior:
- `CreatePlan`/`UpdatePlan` write the plan and its event in one transaction; `UpdatePlan` returns `ErrNotFound` for a missing plan and must not resurrect a CANCELLED plan.
- `PausePlan` is `ACTIVE→PAUSED`; `ResumePlan` is `PAUSED→ACTIVE` with the supplied `next_due_date` and no backfill; `CancelPlan` sets CANCELLED, cancels PENDING_CONFIRMATION occurrences and skips queued manual outbox rows in the same transaction. Illegal transitions return `ErrConflict`.
- `CreateOccurrence` inserts the occurrence, CAS-advances `next_due_date` from `occ.DueDate` to the supplied next date, and writes `OCCURRENCE_CREATED` atomically. Return false when the plan is not ACTIVE, the occurrence exists, or `next_due_date` no longer matches.
- `CreateDispatch` atomically inserts one summary dispatch, its join rows and the outbox delivery. Return false when no supplied occurrence is still PENDING_CONFIRMATION or `(plan_id, local_date, kind)` already exists.
- `TransitionOccurrence` is a compare-and-swap on `payment_status`; same-target replay is idempotent and adds no event; `confirmed_by`/`confirmed_at` are written only for PAID_CONFIRMED.
- `GetPlan`/`GetOccurrence`/`GetDispatch` return `ErrNotFound`; list methods order deterministically and treat `Limit<=0` as unbounded, positive limits bounded.
- `ListManualMessages` returns `telegram_messages` rows linked through the plan's dispatches, ordered by part then id.
- `ManualEvents` returns events ordered by insertion order (rowid), not by caller-supplied time.

Outbox mirror: append manual-dispatch statements to `ClaimDelivery` (SENDING), `expireLeases` (UNKNOWN), `CompleteDelivery` (SENT plus `sent_at`), `FailDelivery` (FAILED/UNKNOWN) and `SkipDelivery` (SKIPPED), in the same transaction as the outbox write. Do not change any existing `invoice_reminders` statement or the outbox semantics.

Tests: fresh migration; upgrade from a v1 database (open with only 0001 applied, then apply 0002); idempotent reopen; unique constraints (plan/day occurrence, dispatch dedup, outbox ID); CAS transitions and idempotent replay; dispatch dedup; outbox mirror through claim/expire/complete/fail/skip; `notified_at` written only for pending occurrences; and a regression assertion that an invoice reminder still transitions exactly as before.
