Commands (exact spellings; unknown or malformed usage returns a clear usage message):
`/reminder_add`, `/reminders`, `/reminder`, `/reminder_edit`, `/reminder_pause`, `/reminder_resume`, `/reminder_delete`, `/reminder_paid`, `/reminder_pending`, `/reminder_history`, `/cancel`.

Callback actions (short prefixes; `callback_data` <= 64 bytes, 32 hex IDs): `mp` (mark paid), `mc` (cancel occurrence), `mu` (undo confirmation), `mv` (view plan), `mh` (history), `mdc` (dispatch detail), plus a separate wizard namespace `wz` (advance/confirm step), `wx` (cancel wizard), `wb` (back one step), `wv` (select value).

Behavior:
- Wizard: `/reminder_add` starts a stateful wizard (title, provider, amount+currency, billing day, reminder time, timezone, payment URL, notes) with `cfg.Manual.WizardTTL` expiry, per-user/per-chat state, validation at each step, back (`wb`), cancel (`wx`) and a final confirmation before `CreatePlan`. Expired state is discarded and reported, never resumed silently.
- `/reminders` lists plans with status and next due date; `/reminder <id>` shows one plan with its pending occurrences; `/reminder_edit` re-enters the wizard pre-filled; pause/resume/delete call the corresponding service methods.
- `/reminder_paid` and the `mp` callback confirm the occurrence; `mu` revokes; both require the authorized user AND configured chat, answer the callback query even when denied, and edit the original message to the new state after a successful transition. A transient edit failure must not undo the persisted state.
- `/reminder_pending` lists pending occurrences ordered by due date; `/reminder_history` lists plan events and dispatches.
- Manual delivery rendering: when `DeliveryPayload.Kind == "manual"`, render the daily summary for `ManualPlanID` and `ManualOccurrenceIDs` — plan title, provider, amount(s), due date(s), payment URL only when it is a trusted HTTPS URL, and the paid/pending state. Reuse the existing escaping and chunking path; every part is independently valid escaped HTML and <= 4096 UTF-16 units; never truncate content.
- All existing authorization, chat-whitelist, rate-limit, retry and message-edit behavior is preserved for manual paths.

Tests: wizard step progression, validation failures, TTL expiry, cancel and back; authorization denial for foreign user and foreign chat (callback answered, no state change); rendering of a manual summary with multiple occurrences; HTML escaping of hostile title/notes/URL; 4096 UTF-16 chunking with long Unicode content; 64-byte callback data; message edit after confirm and after revoke; nil manual service keeps existing behavior; `New` still compiles and behaves as before.
